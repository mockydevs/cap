# Security model and reporting

Report suspected vulnerabilities privately to the repository owners. Do not include production secrets, personal data, raw transcripts, presigned URLs, or working exploit payloads in a public issue.

## Trust boundaries

- Every recording, upload, transcript, edit, AI job, artifact, comment, analytics event, and search document is scoped by `workspace_id` in server-side queries.
- Browsers receive short-lived authorized S3 operations, never AWS credentials. Object keys are generated by the server.
- Media, render, transcription, and AI queues have distinct workers. The AI worker receives approved transcript text from PostgreSQL and has no S3 credentials.
- Share links and presigned URLs are bearer credentials. They must not appear in logs, analytics referrers, support tickets, or monitoring payloads.
- Uploaded media and transcript text are untrusted input. FFmpeg runs in a constrained worker; AI prompts delimit transcript content and outputs are schema-validated suggestions until accepted.
- User-configured AI and webhook destinations are HTTPS-only on port 443, are rejected when they resolve to local/private/reserved addresses, and are rechecked immediately before outbound requests. Redirects are not followed. Operators may explicitly permit exact private or non-standard-port hostnames with `OUTBOUND_PRIVATE_HOST_ALLOWLIST` for intentional services; keep that allowlist narrow and pair it with network-level egress controls in production.

## Secret handling

Keep runtime secrets in Coolify's secret store or a workload-identity mechanism. Never use a `NEXT_PUBLIC_` name for server secrets. Rotate OAuth, AWS, AI, database, Redis, analytics-HMAC, and desktop exchange secrets independently. GitHub deployment access should use OIDC rather than stored AWS access keys.

Production activation requires a cross-tenant authorization test suite, dependency/container scanning, external review of IAM and bucket policies, and the restore/load/failure exercises in `docs/OPERATIONS.md`.

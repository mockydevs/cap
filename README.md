# Cap

An independent, browser-first screen recording platform with authenticated workspaces, resumable private AWS S3 uploads, and asynchronous FFmpeg processing.

## Prerequisites

- Node.js 22+
- pnpm 10+
- A Chromium-based browser for the capture prototype

## Run locally

```bash
cp .env.example .env.local
pnpm install
pnpm dev
```

Open http://localhost:3000. Screen capture requires a secure context: `localhost` is permitted by browsers; deployments must use HTTPS.

## Checks

```bash
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

## AWS object storage

Production media belongs in a private AWS S3 bucket. Use `AWS_REGION`, `AWS_S3_BUCKET_NAME`, `AWS_KMS_KEY_ARN`, and workload-scoped credentials; do not expose S3 credentials with `NEXT_PUBLIC_` variables. The API generates short-lived multipart presigned requests after workspace authorization. See [infra/README.md](infra/README.md) for the required bucket posture and Coolify variables.

## Local services

`docker compose up -d` starts PostgreSQL, Redis, and the media worker. Apply the Drizzle migrations before serving web requests.

The lockfile is generated by `pnpm install` in a Node-enabled development or CI environment and must be committed before the first production build.

## Accounts and workspaces

Sign-up creates a user, personal workspace, and owner membership in one transaction. Passwords use Argon2id, and opaque sessions are stored as SHA-256 token digests while the browser receives a secure HTTP-only cookie. Upload routes resolve their workspace from that session and require at least the member role; they never accept a workspace identity from client input.

Upload routes create private S3 multipart uploads, sign each part for five minutes, and complete the upload server-side. Browser retry state and source blobs are retained in IndexedDB.
